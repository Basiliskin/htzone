# How it was tested (details)

*The README keeps a summary and the example searches; this is the full list (D47).*

- **Unit (domain search logic):** a table-driven test of every normalizer rule (prefixes, plurals, final letters, aliases, niqqud, stop-words, qualifiers) and one hand-made test per ranking rule. Each ranking test was confirmed to **fail** when its rule is switched off (mutation check, SESSION-LOG S2).
- **Integration:** the SQLite repository against a real temporary DB opened read-only, including hostile input (`" OR 1=1 --`, `'; DROP TABLE`, `NEAR(` …) searched as plain text.
- **HTTP (integration, Kernel called directly, no server):** response shape, every error code, 404/405/HEAD, all four security headers on every response kind, cache headers, `/health` 200 and 503 (missing, corrupt and empty DB), a thrown error and a PHP warning both give a generic 500 with details only in the log, `<script>` in `q` comes back as `\u003C…`, and the fields of the log line. Mutation-checked (remove `JSON_HEX_TAG`, a header, HEAD body stripping, logging, or the empty-catalog rule → a test fails). Then `curl` against the dev container and the prod image; CI repeats the smoke (one CSP header, non-root, `/health`, a search, a 400).
- **Frontend (S5):** `node --test` unit tests for query limits, state transitions, an old response never replacing a newer one, Back/Forward rules and API error mapping (D36), each mutation-checked. PHP tests assert the page has no inline script/style (CSP), works as a form without JS, and has every element the script needs. Manual pass in Chrome: all six states (a seventh, `filtered`, was added with the filters and is covered by E2E), retry focus, `/` and `Esc`, Back/Forward, a broken image → fallback, `<script>` and `" OR 1=1 --` shown as text, no CSP violations in the console; 360 px checked with real device emulation (no horizontal scroll, list cards).
- **E2E (S6, Playwright, Chromium):** one spec, five flows in a real browser against the real server (the two filter flows are described under *Filters*): type "שואב אבק" → 8 skeleton cards → real cards with a decoded image, a name and a `₪1,234` price; a nonsense query (`zzqxv`) → the no-results panel with the query and suggestion chips; a faked 500 → error panel → Retry sends the same query to the real API, shows the missing-model notice for "iPhone 16", and focuses the results heading. To see the skeleton, the test holds the request with `page.route` and then lets it reach the real server (D37). In CI it runs against the prod container from the smoke test (D38). Stable over 15 repeated runs; mutation-checked (no skeletons, Retry running nothing, raw agorot instead of ₪, no focus after Retry → each one fails a test).
- **Final QA ([`qa-report.md`](qa-report.md)):** every requirement mapped to its test; all suites re-run; the example queries plus adversarial ones (typo, prefixed plural, English-only brand, mixed, gibberish) run locally and live with top 5 and latency; a security smoke (empty, 10k-char, FTS/SQL characters, `<script>`, RTL marks, emoji, niqqud, backend down, broken images, headers, secrets in history); a browser pass at 360 px and desktop (keyboard, focus, `aria-live`, every state).
- **Filters (D43–D46):** unit tests for `SearchFilter` (parsing, inclusive bounds, bad values), `Facets` (counts, each facet ignoring its own filter) and the use case (24 cap after filtering, reaching past the first 24, strong matches only, no typo fallback when only the filter removed products); API tests for `cat`/`min`/`max`, `facets` and `invalid_filter`; JS tests for URL state and the `filtered` state; two E2E flows (chip → exact count → budget → Back → new query; a filter with no matches → "נקו סינון"). The E2E flows were mutation-checked and stable over 50 runs under CPU load. All 28 relevance rows still pass.
- **Accessibility:** Lighthouse Accessibility **100** on the live site (Chrome DevTools, Incognito, 2026-11-26), above the ≥ 95 target in `docs/design.md`. It is an automated check only; keyboard use, focus and screen-reader announcements were checked by hand in QA (`qa-report.md`).
- **Relevance:** every row of the example-query table ([`docs/requirements.md` §4](requirements.md), the brief's 5 examples + 21 of ours) runs against the real imported catalog, plus a p95 < 100 ms check (real searches take 0.3–5 ms). Two rows failed at first and were fixed in ranking and data, never by relaxing the test (SESSION-LOG S3).
