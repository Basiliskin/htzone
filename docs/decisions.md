# Settled decisions

Source of truth for the role skills — **do not re-ask these**. Append new ones as `D<n> — decision → reason`. Settled 2026-11-26 in a planning (grilling) session with Claude.

| # | Decision | Reason |
|---|---|---|
| D1 | **Plain PHP 8.3** in Docker (Composer, PDO, PHPUnit, SQL migrations). No Laravel, no Node backend. | PHP is preferred by the brief; the author is new to PHP, so minimal "magic" means every line can be explained in the interview. |
| D2 | **Search = offline AI enrichment + plain full-text search at runtime.** Claude writes HE+EN tags per product (synonyms, cross-language spellings such as אייפון↔iPhone, plurals/prefixed forms, use-cases, "gift for…"), committed as data. No AI, model or API key at runtime. | One self-contained deploy, no secrets, <50 ms search. Rejected: embedding API at runtime (external dependency + key) and a local model on the server (memory-heavy on free hosts, PHP can't run it easily). Trade-off: unusual phrasing not covered by tags can miss → README limitation; embeddings as "next". |
| D3 | **Hebrew morphology handled in code**: per query word, try as-typed + stripped attached prefixes (ו ה ב ל מ ש כ) + stripped plural suffixes (ים, ות) + English plural rule; prefix matching (`word*`); a small alias list (אייפון=iPhone, דייסון=Dyson…). Original form ranks higher than stripped forms. | No Hebrew stemmer exists in FTS5; ~40 lines, fully unit-testable. |
| D4 | **Prices are generated**: deterministic (fixed seed), realistic ranges per category, stored in agorot; disclosed in the README; short email to Mor asking about intent. | The CSV has no price column but results must show a price. |
| D5 | **SQLite + FTS5**, DB built inside the Docker image from committed CSV + enrichment. Catalog is read-only at runtime. | One container, no DB password, fast. Repository interface makes Postgres a single new class later. |
| D6 | **Frontend: plain HTML + modern CSS + vanilla JS modules, no build step.** Modern, responsive, mobile-first (1/2/4 columns), RTL, skeleton loaders, no-results with suggestions, error + retry, 250 ms debounce, query synced to URL (`?q=`). | Polished without framework overhead; keeps one container and a strict CSP with no third-party scripts. |
| D7 | **Architecture: light DDD.** Domain (`Product`, `Money`, `SearchQuery`, `HebrewNormalizer`, `ProductRepository` interface) / Application (`SearchProducts`) / Infrastructure (SQLite repository, CSV importer, price generator, migration runner) / Http (JSON controller). Constructor injection in one composition root, no DI container. Interfaces only where swapped/mocked. Strict PHPStan, `strict_types`. | Production-grade means robustness, not ceremony; no aggregates/events because the catalog is read-only. |
| D8 | **Production concerns — build**: input validation + length limit, prepared statements, FTS5 escaping, output escaping, CSP + security headers, JSON errors without stack traces, structured stdout logs, `/health`, cache headers, lazy images + fallback, env config, non-root container, pinned deps, GitHub Actions CI (PHPStan, CS Fixer, PHPUnit), a11y basics. **README only**: rate limiting, pagination, monitoring/metrics, CDN, query cache, search analytics, embeddings. | Cheap items give real production quality; the rest is documented as "with more time". |
| D9 | **Tests**: unit (normalizer, Money, price generator), integration + relevance (the brief's 5 example queries each expect the right product in the top 5, against a real temporary SQLite DB), one Playwright E2E (first to cut if short on time). All in CI. | "How did you test it" is a fixed interview question; relevance tests are the strongest evidence. |
| D10 | **Hosting: Render free (Docker) + keep-awake ping** (cron-job.org → `/health` every 10 min during review). Cold-start trade-off noted in README. | Fastest path to a live URL from GitHub; standard Dockerfile keeps Cloud Run as an easy move. |
| D11 | **Enrichment workflow**: Claude Code writes tags in batches of ~50 into `data/enrichment.jsonl`; a committed check script validates coverage/format; ~20-product human spot-check; fixes logged. Ranking: exact brand/model > name > tags/category > description (FTS5 BM25 field weights), top 24 results, no pagination. | Reproducible, no API key, and gives concrete "how I verified Claude's output" evidence. |
| D12 | **Process**: small commits per build step; `docs/ai-log/SESSION-LOG.md` kept from the start (prompts auto-logged by hook). Time budget: ~5.5–6 h, overrun stated openly in the submission as a deliberate choice for production quality. | History and the Claude log are graded deliverables. |
| D13 | **Workflow tooling**: generic role skills in `.claude/skills/` (product, architect, designer, data, developer, devops, qa, interview) + this file and `docs/stack.md` as project input. Committed, except `/interview` (git-ignored, prompts not logged). Hooks on: prompt logger + PHP check after edits. | Shows the Claude process to reviewers; reusable for future assignments. |
| D14 | **No iPhone 16 in the catalog**: `/data` tags the Apple phones (P0401, P0407, P0413) with iPhone/אייפון; when a Query has a model/version token (e.g. `16`) that no Result contains, show "לא נמצא דגם מדויק, הנה המוצרים הקרובים". | Honest and store-like; shows the data gap was noticed instead of faking a match. |
| D15 | **Typo fallback**: a second FTS5 index with the trigram tokenizer, queried only when the main search returns 0 Results; shown as "האם התכוונת…". | Cheap (~30–40 min), doesn't disturb normal ranking, good demo point. |
| D16 | **Scope (MoSCoW)** as in `docs/requirements.md` §5. Cut order if short on time: Could items → Playwright. | Fits the ~5.5–6 h budget (D12). |
